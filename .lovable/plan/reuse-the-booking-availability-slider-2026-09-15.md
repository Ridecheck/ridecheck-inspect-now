# Reuse the booking availability slider

Replace the newly added list-style availability screen in the mobile Check Availability sheet with the same date and time picker already used in the booking flow.

## Changes

- Use the existing horizontal day slider with **This week / Next week** controls.
- Show the same available, full, weekend, and same-day states generated by the existing booking availability logic.
- After a day is selected, show the existing **Morning / Afternoon** time-window choices.
- Require a valid day/time choice before the customer can continue to package selection.
- Keep the chosen timing in the sheet state and show it in the booking handoff summary.
- Pass the selection into the existing booking page where supported, avoiding a separate mock day generator.

## Technical details

- Reuse `StepTiming` and `buildAvailability` rather than duplicating the booking slider markup or date rules.
- Generate availability from the entered suburb/postcode and the currently selected default package price.
- Remove the temporary `buildDays` and `DayOption` implementation from the availability sheet.
- Keep the mobile sheet’s existing progress, success animation, package step, and handoff unchanged.

## Validation

- Verify horizontal swiping, week switching, unavailable-day handling, and Morning/Afternoon selection on a phone-sized screen.
- Verify Back navigation retains the selected timing and the final handoff displays it correctly.
- Confirm the existing `/book` booking flow remains unchanged and the project builds without errors.
